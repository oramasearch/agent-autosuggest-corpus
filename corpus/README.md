# autosuggest-sft-corpus

**SFT training data for the Auto-Suggest model.** Private. Internal-confidential.
Generated by `zetta-bridge/modules/agent-autosuggest-corpus` ([zetta#986](https://github.com/oramasearch/zetta/issues/986)).

One example is **(profile → project profile)**: given a business situation and its data, what is
worth building. The `project_profile` output is **the same shape the project-creation agent
consumes**, so Auto-Suggest and the project agent compose without a translation layer that can
drift.

## Not the eval set — deliberately

`OramaSearch/agent-eval-profiles` is the **test set** for the model this trains. Overlap would
make every eval score a measurement of memory rather than reading, and nothing downstream could
tell the difference.

So this corpus generates its own situations, and the generator **refuses to start** if it cannot
load the eval set to check against. Near-misses count: >60% overlap of industry and table names is
rejected. Off-limits industries are given to the model up front rather than rejected after the
call.

## What every example must satisfy

Each check exists because something weak got through without it:

- **`solution` is a catalogue id** (`S-1`, `UC-13`), never prose — the id is what lets the project
  agent look up the correctness profile the pipeline must satisfy.
- **Constraints narrow the answer.** *"Must provide actionable insights"* is decoration; a real
  constraint carries a number, a prohibition, or an ordering.
- **`fits_the_constraint` does not restate the constraint** — it says what about the *output*
  satisfies it.
- **A declined item's answer matches its reason.** *"Capture it first"* only for a
  discovered-but-uncaptured source; data lacking a label is not fixed by capturing it.
- **Forecast is never calibrated** (no probability to calibrate); **supervised always has a
  holdout** (or it cannot quote an honest figure); **something is always declined** (a model that
  always suggests will suggest something worthless).

## Limitations — read before using

- **      17 examples.** Small. This is a first batch, not a trained-on corpus.
- **Roughly half of generations are rejected**, mostly for vague constraints. The rejections are
  genuine and the checks are deliberately strict, but it means yield is low and the kept examples
  skew toward whatever the model finds easy to constrain concretely.
- **Nothing has been trained on this**, so there is no evidence it teaches what it intends to.
- **Synthetic.** No situation is drawn from a real customer.
