**Released 2026-11-16. A minor release.** Since [v0.2.0](v0.2.0.md): the licence, the security policy, base images pinned by digest and the public-tree cleanup. Image: `docker.io/oramasearch/agent-autosuggest-corpus:v0.3.0`, not published (see *Known issues*).

This release is the tree of `dev` with these notes and the version.

### The public-tree cleanup — #26

Nothing internal is left in the files that will be published: `.public-exclude` was added and then removed again once the agent files were rewritten to ship publicly; the corpus card is MIT and no longer marked internal; a tracker URL in `fixtures/solutions.json`, `corpus/autosuggest-sft-v3.jsonl` and one test became the plain reference `zetta#1102`; the eval set is named by its public source, `agent-eval-generator`'s `evals/profiles/`. No code change.

### The licence — #25

Everything in this repository that Orama wrote is under the MIT licence. Contributors sign `CLA.md` once. `THIRD_PARTY_LICENSES` lists every runtime dependency with its licence text; none is incompatible with MIT distribution.

## Known issues

Security-relevant first. All open at this tag.

1. #27 (release blocker for publishing): the image is built on `python:3.12-slim`, which bundles GPL and LGPL userland, so **the image is not published**. It is built and kept in the project's non-public Docker Hub repository until it moves to a scratch base with static binaries.
2. #28: `tests/test_solutions.py::test_enforcement_stamps_composition_and_declines_non_runnable_solution` fails. The test still expects the tracker URL that #26 replaced with `zetta#1102`; the code behaves as intended. Found by this release.
3. #6: the task's workspace is not passed explicitly on receive, claim, publish and `workspace_query`. Lake scopes the task credential to the task's workspace, so a turn cannot reach another workspace.
4. #15: corpus drafts generated through Lake fail validation for S-1 (the examples do not choose a registry level), and the turn fails with nothing created.
5. The lease is kept by activity only, and the receive cursor is in memory (unchanged from v0.2.0).

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes run the operator's default image of this agent; the changes since v0.2.0 are proven by the test suite only. Moving a Lake to `:v0.3.0` is a separate operator change.
