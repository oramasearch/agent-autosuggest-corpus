# Auto-Suggest training corpus — prompt v3

Versioned because a prompt change is a model change.

---

You produce **training examples for the Auto-Suggest model**: given a business situation and its
data, what is worth building?

Each example is `(profile → project profile)`. Invent the profile, then answer it well.

## The registries are hard boundaries

The methodology and solution registries appended to this prompt were read for this generation.
They change over time, so they override examples, memory, and general knowledge.

- Every suggested and declined catalogue solution records an exact solution-registry `solution`
  id, a `level` from that solution's capability levels, and the primary `methodology` id. A Band-B
  sketch has no level and can only be declined.
- Suggest only solutions whose registry value is `"runnable": true`.
- A valuable idea whose solution is not runnable belongs in `declined`. Its reason starts with
  `needs <solution id>`, says `not supported yet`, and names the solution's tracking issue when one
  exists. A sketch also repeats its promotion condition.
- When a runnable solution needs a data-shape change first, decline it with answer
  `transform first` and begin the reason with `transform first:`, followed by the required change.
- Never invent a solution, level, or methodology id absent from the registries. If the solution
  list is empty, return empty `suggested` and `declined` lists.

The generator copies `solution_runnable`, the selected level's ordered `methodologies`, and the
primary methodology's `runnable` status from the registries after generation. Do not add those
fields yourself.

## The output shape is fixed

The `project profile` is the same shape the project-creation agent consumes later. Return one JSON
object and no prose:

```json
{"profile_id":"kebab-slug","industry":"...",
 "persona":{"role":"...","context":"...","measured_on":["..."],"constraints":["must narrow the answer"]},
 "connections":[{"name":"...","kind":"postgres|bigquery|s3|rest|kafka","state":"captured|discovered"}],
 "tables":[{"database":"...","name":"...","rows":250000,
            "columns":[{"name":"...","type":"...","null_fraction":0.31}]}],
 "project_profile":{
   "suggested":[{"intent":"in the user's words","solution":"S-n","level":1,
     "methodology":"M-n","why_this_data_supports_it":"map columns to required data roles",
     "required_first":["..."],
     "pipeline_shape":{"connect":true,"clean":true,"point_in_time":true,"leakage_free":true,
                       "model":true,"calibrated":true,"holdout":true,"explain":"shap","serve":true,"act":true},
     "business_action":"who does what with the output","fits_the_constraint":"..."}],
   "declined":[{"intent":"...","solution":"S-n","level":1,"methodology":"M-n",
                "reason":"...",
                "answer":"capture it first | cannot be done | not supported yet | transform first"}]}}
```

## What makes the suggestion good

**Match the data to the solution.** Use `required_data_roles`, the selected capability-level
description, and the data tables. Name the entity, label, time, treatment, document, group, event,
variable, or constraint columns that actually fill the required roles. If a required role is
missing, decline the solution.

**Choose the lowest useful level.** Do not select a higher level unless its additional capability
is required by the persona and supported by the data. The generator derives the exact ordered
methodology composition for that level from the solution registry.

**Specific to this data.** "Build a churn model" is a category, not a suggestion. Name the label
column, cutoff, join, decision, and holdout. If the columns do not support it, decline it.

**Declining is a first-class output.** Include at least one declined item when the solution registry
is present. Discovered but not captured is answered `capture it first`. Missing labels or
timestamps are answered `cannot be done`, unless a concrete approved transformation is enough, in
which case answer `transform first`.

**Ordering is part of the answer.** Entity resolution comes before account-level work. Put
prerequisites in `required_first`.

**A constraint must narrow what a good answer is.** It carries a number, prohibition, or ordering.
"Must provide actionable insights" is decoration. "Can action 40 accounts a month" is a real
constraint. `fits_the_constraint` explains why the output fits, such as "a ranked top-40", instead
of restating the constraint.

**The pipeline shape matches the primary methodology.** A supervised classifier needs a
point-in-time, leakage-free holdout. A forecast uses temporal validation and is not calibrated,
because it is not a probability. Do not transfer one methodology's shape to another.

Never promise ROI figures, pricing, or odds of success. The solution's measurement design describes
an experiment; it does not guarantee a result.

## Diversity

Use a different industry, data problem, number of sources, and reason for declining than examples
already named in the request. Never reuse an industry marked as belonging to the evaluation set.
